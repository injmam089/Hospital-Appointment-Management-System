# HAMS Phase 12 — API Reference Documentation

**Project:** Hospital Appointment Management System (HAMS)  
**Base URL:** `http://localhost:8055/api` (Local) / `/api` (Production Proxy)  
**Standard Error Specification:** RFC 7807 `ProblemDetail` (`application/problem+json`)  
**Status:** Verified Production API  

---

## 1. Global API Standards & Error Handling

### 1.1 Authentication & Header Requirements
All authenticated endpoints require the standard Bearer token header:
```http
Authorization: Bearer <JWT_ACCESS_TOKEN>
Content-Type: application/json
```

### 1.2 RFC 7807 `ProblemDetail` Specification
All error responses generated by `GlobalExceptionHandler` and Spring Security conform to RFC 7807.

**Example Conflict Response (HTTP 409):**
```json
{
  "type": "https://hams.example.com/errors/conflict",
  "title": "CONFLICT",
  "status": 409,
  "detail": "This appointment slot has already been booked. Please choose another time.",
  "instance": "/api/patient/appointments",
  "timestamp": "2026-10-09T09:27:02.713182919Z"
}
```

**Example Validation Error Response (HTTP 422):**
```json
{
  "type": "https://hams.example.com/errors/validation_error",
  "title": "VALIDATION_ERROR",
  "status": 422,
  "detail": "Input validation failed. Please check the errors and try again.",
  "errors": {
    "email": "Please provide a valid email address",
    "password": "Password must be at least 8 characters long"
  },
  "timestamp": "2026-10-09T09:27:02.713182919Z"
}
```

## 2. Authentication & Public Discovery Endpoints

### `POST /api/auth/register`
- **Purpose:** Register a new patient account and initialize demographic profile.
- **Auth Requirement:** Public (Rate Limited)
- **Request Body:**
  ```json
  {
    "email": "new.patient@example.com",
    "password": "Password@123",
    "firstName": "John",
    "lastName": "Doe",
    "phone": "+919876543210",
    "gender": "MALE",
    "dateOfBirth": "1990-05-15",
    "bloodGroup": "O+"
  }
  ```
- **Response (201 Created):** `AuthResponse` containing `accessToken`, `refreshToken`, and sanitized `user` object.

### `POST /api/auth/login`
- **Purpose:** Authenticate credentials (Patient, Doctor, Admin) and receive JWT token pair.
- **Auth Requirement:** Public (Rate Limited)
- **Request Body:**
  ```json
  {
    "email": "patient.demo1@example.com",
    "password": "Patient@HAMS2024!"
  }
  ```
- **Response (200 OK):**
  ```json
  {
    "accessToken": "eyJhbGciOi...",
    "refreshToken": "eyJhbGciOi...",
    "tokenType": "Bearer",
    "expiresIn": 900000,
    "user": {
      "id": 1,
      "email": "patient.demo1@example.com",
      "role": "PATIENT",
      "firstName": "Rahul",
      "lastName": "Sharma",
      "fullName": "Rahul Sharma"
    }
  }
  ```
- **Error Codes:** 400 Bad Request (Invalid credentials), 429 Too Many Requests.

### `POST /api/auth/refresh`
- **Purpose:** Issue a new Access Token using an active, unexpired Refresh Token.
- **Auth Requirement:** Public
- **Request Body:** `{"refreshToken": "eyJhbGci..."}`
- **Response (200 OK):** `{"accessToken": "eyJhbGci...", "expiresIn": 900000}`
- **Error Codes:** 401 Unauthorized (Invalid or expired refresh token).

### `GET /api/public/health`
- **Purpose:** Liveness and readiness probe for orchestration and load balancers.
- **Auth Requirement:** Public
- **Response (200 OK):** `{"status": "UP", "service": "HAMS API", "version": "1.0.0"}`

### `GET /api/public/doctors`
- **Purpose:** Browse verified and active doctors with optional search and department filter.
- **Auth Requirement:** Public
- **Query Params:** `search` (string), `departmentId` (long), `page` (int), `size` (int).
- **Response (200 OK):** Paginated `PageResponse<DoctorProfileResponse>`.

### `GET /api/public/departments`
- **Purpose:** Retrieve list of active medical departments.
- **Auth Requirement:** Public
- **Response (200 OK):** `List<DepartmentResponse>`.

### `GET /api/doctors/{doctorId}/slots`
- **Purpose:** Retrieve available 30-minute booking slots for a specific doctor on a chosen date.
- **Auth Requirement:** Public
- **Query Params:** `date` (YYYY-MM-DD, Required).
- **Response (200 OK):** `DoctorDaySlotsResponse` containing array of `time` and `available: true/false`.

## 3. Patient Portal API (`/api/patient/**`)

All endpoints in this section strictly require `ROLE_PATIENT`.

| Method | Endpoint | Purpose | Request Body | Response (Success) |
|---|---|---|---|---|
| `GET` | `/api/patient/profile` | Fetch patient profile | None | `PatientProfileResponse` (200) |
| `PUT` | `/api/patient/profile` | Update demographics | `UpdatePatientProfileRequest` | `PatientProfileResponse` (200) |
| `GET` | `/api/patient/appointments` | List patient's appointments | None | `List<AppointmentSummaryResponse>` (200) |
| `POST` | `/api/patient/appointments` | Book an appointment | `BookAppointmentRequest` | `AppointmentDetailsResponse` (201) |
| `GET` | `/api/patient/appointments/{id}` | Fetch appointment detail | None | `AppointmentDetailsResponse` (200) |
| `PATCH` | `/api/patient/appointments/{id}/reschedule` | Reschedule appointment | `RescheduleRequest` | `AppointmentDetailsResponse` (200) |
| `PATCH` | `/api/patient/appointments/{id}/cancel` | Cancel appointment | `CancelAppointmentRequest` | `AppointmentDetailsResponse` (200) |
| `GET` | `/api/patient/prescriptions` | List digital prescriptions | None | `List<PrescriptionResponse>` (200) |
| `GET` | `/api/patient/prescriptions/{id}` | Fetch prescription detail | None | `PrescriptionResponse` (200) |

## 6. Real-Time Notification API (`/api/notifications/**`)

Authenticated endpoints accessible by any active user for their own notifications.

| Method | Endpoint | Purpose | Request Body | Response (Success) |
|---|---|---|---|---|
| `GET` | `/api/notifications` | List user's notifications (ordered by date) | None | `List<NotificationResponse>` (200) |
| `GET` | `/api/notifications/unread-count` | Badge counter for unread notifications | None | `{"count": 3}` (200) |
| `PATCH` | `/api/notifications/{id}/read` | Mark individual notification as read | None | `NotificationResponse` (200) |
| `PATCH` | `/api/notifications/read-all` | Mark all user notifications as read | None | 204 No Content |
